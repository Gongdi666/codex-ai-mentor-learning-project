# セッションの開始・引き継ぎと終了報告

## 適用前の確認

プロジェクトルートの [AGENTS.md](../../../AGENTS.md) と [PROMPT.md](../../../PROMPT.md) を未読なら先に読んでください。両方の共通ルールを守り、このスキルを編集許可として扱わないでください。本文中の `/docs/` などは、ファイルシステムのルートではなくプロジェクトルートからのパスです。

## 実行手順

1. 開始・再開時は第29節と第12.4節に沿って状況を復元してください。既に読んで内容を保持しているファイルを循環して読み直す必要はありません。
2. ログの整理・更新時は第13節で保存先を確認してください。開始しただけで終了報告の処理は行わないでください。
3. `終了報告` の入力時は第28節を実行してください。`クライアント終了` とは別の操作です。
4. 読み込めなかったファイルや保存できなかったログは明示し、実行済みとして扱わないでください。

以下はPROMPT.mdから移した詳細ルールです。照合しやすいよう、元の節番号を残しています。

## 12. ディレクトリルール

このプロジェクトでは、以下のディレクトリを使用します。

### 12.1 ログファイル配置

ログファイルは以下に配置します。

- `/docs/logs/AI_mentor_log.md`
- `/docs/logs/Agenda_log.md`

### 12.2 コンテキストファイル配置

設計方針の前提、学習用メモ、現在タスク、決定事項、未決事項などのMarkdownファイルは以下に配置します。

- `/docs/context/`

### 12.3 設計書ファイル配置

ユーザー主体で作成する要件定義書、基本設計書、詳細設計書、データ設計書、API設計書、画面設計書、テスト設計書などは以下に配置します。

- `/docs/architecture/`

`/docs/architecture/` 配下のMarkdownファイルは、ユーザー主体の設計成果物です。
通常時はレビュー・助言・雛形案の提示を中心に支援し、ユーザーから明示的な編集指示がある場合は直接編集・新規作成して構いません。

### 12.4 読み込み対象

あなたが文脈を復元する際は、原則として以下を読み込んでください。

- `/PROMPT.md`
- `/AGENTS.md`
- `/README.md`
- `/docs/context/`
- `/docs/logs/`
- `/docs/architecture/`

特にVSCode再起動後や新しいセッション開始時は、以下を優先して確認してください。

1. `/AGENTS.md`
2. `/docs/context/current_tasks.md`
3. `/docs/context/architecture_summary.md`
4. `/docs/logs/AI_mentor_log.md`
5. `/docs/logs/Agenda_log.md`
6. `/docs/architecture/`

読み込めないファイルがある場合は、推測で補完せず、存在しないことを明示してください。

## 13. ログ管理

以下のログファイルを使用します。

### 13.1 AI_mentor_log.md

通常のメンター活動、学習内容、設計レビュー、実装レビュー、次回タスクを記録するログです。

配置場所：

`/docs/logs/AI_mentor_log.md`

主な記録内容：

- 今日の作業内容
- 学習した内容
- 設計上の判断
- レビュー結果
- 未解決事項
- 次回タスク
- ユーザーがつまずいた点
- 次に重点的に学ぶべき内容

### 13.2 Agenda_log.md

PMモードにおける、PMであるあなたとクライアントであるユーザーのやり取りを記録する議事録ログです。

配置場所：

`/docs/logs/Agenda_log.md`

主な記録内容：

- 会議概要
- ヒアリング内容
- 決定事項
- 未決事項
- 確認事項
- 次回アクション
- 要件定義に反映すべき内容

## 28. 終了報告

ユーザーが `終了報告` と入力した場合、以下を行ってください。

- 今日の作業内容総括
- 学習内容整理
- 次回タスク整理
- 永続コンテキスト更新案の提示
- `/docs/logs/AI_mentor_log.md` への追記・更新

`/docs/logs/AI_mentor_log.md` は編集許可対象のため、必要に応じてあなたが直接追記・編集して構いません。

終了報告時に `/docs/logs/Agenda_log.md` を編集する必要はありません。
`/docs/logs/Agenda_log.md` は、PMモード中の議事録、または `クライアント終了` 入力時の議事録保存で使用してください。
